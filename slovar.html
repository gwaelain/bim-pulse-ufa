Словарь BIM-терминов

Короткие определения без воды: что означает термин и чем он важен на практике. Где у нас есть подробный разбор — стоит ссылка.

BIM

Способ работы, при котором здание описано не чертежами, а моделью с данными: у каждого элемента есть геометрия и свойства (марка, материал, объём). Из этих данных потом считают смету, график и закуп.

Также говорят: Building Information Modeling, ТИМ, информационное моделирование

LOD

Уровень проработки элемента модели: насколько точна геометрия и насколько заполнены данные. LOD 200 — обобщённый объект, LOD 350 — с узлами и привязками. Это договорённость в задании, а не свойство файла.

Также говорят: уровень проработки, Level of Development

LOI

Уровень информационной наполненности: какие параметры обязаны быть заполнены у элемента. Часто путают с LOD: можно иметь подробную геометрию и пустые данные — для сметы это бесполезно.

Также говорят: Level of Information, уровень информации

CDE

Среда общих данных — единое место, где лежат актуальные версии моделей и документов, с правилами именования, статусами и историей. Не папка на диске, а процесс: кто, что и когда имеет право менять.

Также говорят: СОД, среда общих данных, Common Data Environment

Разбор из практики →

Сводная модель

Модель, собранная из файлов всех разделов (АР, КР, ОВ, ВК, ЭОМ) для совместной проверки. Разделы остаются отдельными файлами, в сводной они только связаны — по ней ищут коллизии и считают объёмы.

Также говорят: федеративная модель, объединённая модель

Разбор из практики →

Коллизия

Конфликт между элементами разных разделов: пересечение воздуховода с балкой, недостаточный зазор для монтажа. Делятся на жёсткие (физическое пересечение) и мягкие (нарушение зазора или зоны обслуживания).

Также говорят: clash, пересечение, столкновение

Разбор из практики →

IFC

Открытый формат обмена моделями между разными программами. Из Revit выгружается с настройками, и именно в них теряются данные: без нужных наборов свойств смежник получит геометрию без марок и материалов.

Также говорят: Industry Foundation Classes, обменный формат

Разбор из практики →

Dynamo

Среда визуального программирования внутри Revit: алгоритм собирается из блоков, без написания кода. Решает массовые задачи — нумерация, заполнение параметров, выгрузка данных в Excel.

Также говорят: Динамо, визуальное программирование

Разбор из практики →

pyRevit

Бесплатное расширение для Revit, которое позволяет добавить свои кнопки на ленту и запускать Python-скрипты. Ставится за десять минут, компилировать и покупать ничего не нужно.

Также говорят: пайревит

Разбор из практики →

Спецификация

Таблица в Revit, которая собирает данные элементов модели по заданным правилам. Считается автоматически и обновляется вместе с моделью — в отличие от таблицы, набранной руками.

Также говорят: ведомость, schedule, таблица

Разбор из практики →

Общие параметры

Параметры, которые живут в отдельном файле и одинаково опознаются во всех проектах и семействах. У каждого — свой GUID: два файла с одинаковыми именами параметров дают пустые столбцы в сводной модели.

Также говорят: ФОП, файл общих параметров, shared parameters

Разбор из практики →

Navisworks

Программа Autodesk для сборки сводной модели и поиска коллизий. Читает форматы разных САПР, работает с тяжёлыми моделями и даёт отчёты, по которым ведут согласование между разделами.

Также говорят: Навис, Невис

Разбор из практики →

Матрица коллизий

Таблица «кто с кем проверяется»: какие разделы и системы сопоставляются между собой и с каким допуском. Без неё проверка «всё против всего» выдаёт тысячи строк, которые никто не читает.

Также говорят: матрица проверок

Разбор из практики →

Точка обзора

Сохранённое положение камеры в Navisworks вместе с настройками отображения. Используется, чтобы показать коллизию смежнику — но выделение элементов в ней сохраняется не всегда.

Также говорят: viewpoint, точка зрения

Разбор из практики →

EIR

Требования заказчика к модели: что моделируем, с какой детализацией, какие параметры заполняем и в каком виде сдаём. Документ, по которому потом принимают работу.

Также говорят: информационные требования заказчика, Exchange Information Requirements

BEP

Ответ исполнителя на EIR: как именно будет организована работа — структура файлов, регламент координации, сроки выдач, кто за что отвечает.

Также говорят: план реализации BIM, BIM Execution Plan

Разбор из практики →

4D

Связка модели с календарным графиком: каждому элементу сопоставлен срок работ, и строительство можно просмотреть во времени. Расхождения графика и модели становятся видны до выхода на площадку.

Также говорят: календарное планирование по модели

Разбор из практики →

Классификатор

Система кодов, по которой элементы модели сопоставляются со сметными расценками и номенклатурой снабжения. Без единого классификатора данные модели не доезжают до сметы без ручного переноса.

Также говорят: кодификатор, классификация элементов

Разбор из практики →

NWC и NWD

NWC — промежуточный файл выгрузки из Revit или другой САПР, NWD — собранная сводная модель одним файлом со всей геометрией. NWF хранит только ссылки на исходники и настройки.

Также говорят: форматы Navisworks

Разбор из практики →

Revit API

Программный интерфейс Revit: позволяет писать плагины на C# или Python, которые делают с моделью то, чего нет в стандартных командах — свои проверки, выгрузки, массовые операции.

Также говорят: программный интерфейс Revit
