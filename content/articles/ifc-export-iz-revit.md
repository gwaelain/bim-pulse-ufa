Смежник открыл наш IFC и написал: «У вас марки нет». В файле было 4 260 элементов и ни одного свойства, по которому их можно отфильтровать. Причина: выключенная галочка Export Revit property sets. Полторы минуты на исправление, три дня на переписку.

IFC ломается редко целиком. Обычно он приезжает внешне нормальным, а проблемы всплывают через неделю, когда по нему уже считают.

## Какую версию ставить

В экспортёре Revit версий 2020-2025 в списке лежит десяток вариантов. Реально используются два.

**IFC 2x3 Coordination View 2.0.** Рабочая лошадь для координации. Её понимают все: Navisworks, Solibri, BIMcollab, Tekla, отечественные просмотрщики. Если смежник не сказал иначе, отдавайте этот вариант.

**IFC4 Reference View.** Точнее описывает геометрию, компактнее по кривым поверхностям, лучше держит параметрические профили. Проблема одна: поддержка на приёмной стороне неровная. Один просмотрщик откроет идеально, второй потеряет часть свойств, третий покажет серые коробки.

Остальные схемы под конкретные задачи: GSA Concept Design под американские требования, Basic FM HandOver под сдачу модели службе, которая будет обслуживать здание, IFC4 Design Transfer View под попытку передать редактируемую геометрию.

Правило простое: версию согласуют один раз на старте, пишут в BEP и больше не меняют посреди проекта. Смена схемы в середине означает, что все ранее настроенные фильтры и правила у смежников перестанут работать.

## Где лежат настройки и что в них важно

File → Export → IFC → Modify setup. Пять вкладок, и на каждой есть по паре пунктов, которые решают судьбу файла.

| Вкладка | Настройка | Что ставить |
|---|---|---|
| General | IFC Version | IFC 2x3 Coordination View 2.0 |
| General | Coordinate base | Shared Coordinates |
| General | Split walls and columns by level | включить, если стены сквозные |
| General | Phase to export | текущая стадия, не «Новая конструкция» по умолчанию |
| Additional Content | Export only elements visible in view | включить и подготовить отдельный 3D-вид |
| Additional Content | Export rooms in 3D views | включить, если нужны IfcSpace |
| Property Sets | Export Revit property sets | включить |
| Property Sets | Export IFC common property sets | включить |
| Property Sets | Export base quantities | включить, если по модели считают объёмы |
| Level of Detail | Tessellation level | Low для координации, High для сложных форм |
| Advanced | Store IFC GUID in element parameter | включить |

Три пункта из таблицы объясню отдельно, потому что именно они чаще всего портят обмен.

**Coordinate base.** Здесь выбирают точку отсчёта. Shared Coordinates даёт файл, который встанет в общую сборку без сдвигов. Internal Coordinates выдаёт модель, уехавшую на координаты площадки, и смежник получает здание в трёх километрах от остальных.

**Export only elements visible in view.** Без этой галочки в файл уедет всё, включая черновые массы, временные объёмы и чужие связи. С галочкой вы контролируете состав: сделайте 3D-вид «IFC_export», настройте видимость по рабочим наборам и фильтрам, проверьте глазами. Этот вид становится частью процесса и живёт в шаблоне.

**Store IFC GUID in element parameter.** Пишет в элемент Revit тот же идентификатор, который уйдёт в IFC. Дальше замечание из BCF или из отчёта по коллизиям находится в модели поиском по GUID, а не «где-то на третьем этаже возле оси Г».

## Маппинг категорий: почему всё стало IfcBuildingElementProxy

Revit сопоставляет свои категории классам IFC по таблице. Открывается она через File → Export → Options → IFC Options: слева категория Revit, справа IFC Class Name и подтип.

Основная беда живёт в категории «Обобщённые модели». Всё, что смоделировано семейством этой категории, уезжает как IfcBuildingElementProxy. Для смежника это означает объект без класса: он не попадёт ни в фильтр по стенам, ни в фильтр по оборудованию, ни в расчёт объёмов. А в «Обобщённые модели» у проектировщиков попадает многое: закладные, нестандартные шахты, ограждения, часть оборудования.

Лечится двумя способами.

Первый: правка таблицы. Меняете класс для категории целиком, сохраняете файл маппинга и раздаёте команде. Работает, когда категория используется однородно.

Второй, точнее: параметры IfcExportAs и IfcExportType. Добавляете их как общие параметры типа (текстовые), пишете значение вроде IfcCovering или IfcRailing, и конкретное семейство уезжает нужным классом независимо от категории. Мы обычно зашиваем эти параметры сразу в шаблон и в основные семейства, тогда рядовой проектировщик про них даже не вспоминает.

Проверить результат просто: открыть выгруженный файл в просмотрщике и посмотреть дерево классов. Если IfcBuildingElementProxy занимает больше пяти процентов элементов, маппинг не настроен.

## Что теряется при экспорте всегда

IFC переносит объём и свойства. Всё, что было логикой Revit, остаётся в Revit.

- Параметрика семейств. Уезжает геометрия в текущем состоянии, ручки и формулы нет.
- Связи и зависимости: привязка стены к уровню, соединения элементов, автоматическое подрезание.
- Двумерное оформление: штриховки, аннотации, размеры, виды. Галочка Export 2D plan view elements переносит немногое и обычно мусорит.
- Заливка помещений, если не включён экспорт IfcSpace. По умолчанию помещения из 3D-видов не выгружаются, и смежник не увидит ни площадей, ни границ.
- Часть параметров экземпляра, если выключены Revit property sets. Тогда остаётся только базовый набор IFC.
- Материалы приходят названиями, а не физическими свойствами.

Отдельная история со стенами и колоннами через несколько этажей. Без Split walls and columns by level элемент уедет одним объектом на всю высоту, и любая поэтажная выборка у смежника поедет. Считать объёмы по этажам по такому файлу нельзя.

## Проверка перед отправкой: 10 минут

Экспорт без проверки это отправка вслепую. Минимальный чек-лист, который экономит дни переписки.

1. Открыть свой же IFC в стороннем просмотрщике. Не в Revit, он покажет слишком лояльно. Подходит любой бесплатный просмотрщик IFC или Navisworks с плагином.
2. Сверить число элементов. В Revit спецификация с фильтром по тому же 3D-виду, в просмотрщике счётчик объектов. Расхождение больше пары процентов означает, что в файл уехало лишнее или недоехало нужное.
3. Ткнуть в пять случайных элементов разных категорий и посмотреть свойства. Марка, тип, уровень, материал на месте? Если пусто, вернитесь на вкладку Property Sets.
4. Проверить точку привязки. Совместите IFC с моделью АР или с топосъёмкой. Сдвиг виден сразу.
5. Посмотреть дерево уровней. Элементы должны сидеть на своих этажах, а не в разделе «Без уровня».
6. Сравнить объёмы по трём позициям: бетон, стены, воздуховоды. Расхождение с ведомостью Revit больше пяти процентов это повод разбираться, а не отправлять.

Пункты 2 и 6 автоматизируются: выгрузка свойств из IFC в таблицу и сверка со спецификацией Revit делается скриптом за пару секунд. На объёмах от десяти файлов в месяц это окупается сразу.

Сам чек-лист стоит записать одной страницей и положить рядом с сетапом экспорта. Люди меняются, а привычка проверять держится на памяти конкретного человека ровно до его отпуска.

Если выгрузок много, заведите лог: дата, версия модели, кто выгружал, что менялось в настройках. Три строки на выгрузку. Зато вопрос «откуда взялся этот файл» закрывается за минуту, а не за полдня переписки.

## Четыре жалобы смежников и что за ними стоит

**«Файл пустой, ничего не видно».** Экспорт шёл с галочкой Export only elements visible in view, а вид оказался с фильтрами или подрезкой. Состав вида проверяют до выгрузки, а не после звонка.

**«Ваш дом стоит в трёх километрах от нашего».** В Coordinate base стояли Internal Coordinates или Survey Point. Ставим Shared Coordinates и отправляем заново.

**«У элементов нет ни одного свойства».** Выключены Revit property sets. Включить и проверить на пяти элементах перед отправкой.

**«Двери у вас не двери, а какие-то прокси».** Семейства сделаны в категории обобщённых моделей. Правится таблицей маппинга или параметром IfcExportAs.

Пятая жалоба стоит особняком: «объёмы в вашем IFC не сходятся с ведомостью». Обычно виноваты выключенные base quantities или сквозные стены без разбивки по этажам. Проверяется на трёх позициях за пять минут.

## Что приложить к файлу

- Схему и версию: IFC 2x3 CV 2.0 или IFC4 RV.
- Дату выгрузки и версию исходной модели.
- Имя вида, из которого шёл экспорт.
- Чего в файле нет намеренно: черновая геометрия, временные конструкции, чужие связи.

Четыре строки в письме снимают половину вопросов. Смежник сразу видит, что перед ним, и не тратит день на выяснение, у кого в цепочке потерялись свойства.

## Что смотреть в чужом IFC на приёме

Входной контроль занимает те же десять минут и снимает половину будущих претензий.

- Схема и версия совпадают с тем, о чём договаривались на старте.
- Файл встаёт в общую сборку без ручного сдвига.
- Доля IfcBuildingElementProxy. Больше пяти процентов, и ваши фильтры работать не будут.
- Есть свойства, по которым вы собираетесь группировать коллизии и считать объёмы.
- Уровни на месте, элементы сидят на своих этажах.
- Не приехала чужая черновая геометрия и связи соседних разделов.

Файл, не прошедший контроль, возвращается автору в тот же день с перечнем замечаний. Принимать «как есть, потом разберёмся» выходит дороже: через месяц по этому файлу уже посчитают объёмы и выпустят задание.

## Чего от IFC ждать не надо

Он не заменяет исходную модель. IFC годится для координации, проверки, подсчёта и передачи заказчику. Проектировать в нём и править его как родной файл нельзя: Design Transfer View обещает больше, чем даёт на практике.

Круговой обмен без потерь не выйдет. Экспорт из Revit, правка у смежника, импорт обратно: каша почти гарантирована. Работают иначе. Каждый ведёт свой раздел в своей программе, а IFC служит для чтения, проверки и подсчёта.

Он не гарантирует одинаковой картинки в разных программах. Один и тот же файл в двух просмотрщиках может показать разное число объектов, потому что каждый по-своему разбирает вложенные сборки. Ошибки экспорта тут нет. Держите это в голове, когда спорите о числах со смежником.

Плохую модель формат не лечит. Кривые уровни, элементы в чужих категориях, мусор из связанных DWG уедут в IFC ровно такими же. Сначала порядок в модели, потом обмен, иначе вы аккуратно упакуете хаос.

## Коротко по частым вопросам

**IFC или NWC для координации?** NWC, если все работают в Revit: он легче и точнее тянет параметры. IFC нужен, когда в проекте больше одной среды проектирования.

**Можно ли по IFC считать спецификации?** Можно, при включённых property sets и base quantities. Выгрузка свойств в таблицу и сверка с ведомостью Revit автоматизируется скриптом за час работы.

**Почему один файл в разных программах показывает разное число объектов?** Разные правила разбора вложенных сборок. Считайте в одной программе и зафиксируйте её в договорённостях по проекту.

**Связи выгружать отдельными файлами?** Да. Export linked files as separate IFCs даёт по файлу на раздел, и смежник обновляет их поштучно. Единый файл со всеми связями неудобно перевыпускать.

**Кто отвечает за выгрузку: автор раздела или BIM-специалист?** Выгружает автор, проверяет координатор. Схема, где за всю компанию выгружает один человек, ломается на первом же его отпуске.

**Как часто отдавать IFC смежникам?** По тому же графику, что и остальные публикации: раз в неделю на активной стадии. Внеплановые выгрузки плодят версии, о которых никто не помнит.

## Следующий шаг

Сделайте одну вещь на ближайшей выдаче: экспортируйте по чек-листу выше и откройте свой файл сторонним просмотрщиком до отправки. За десять минут вы увидите, что именно получает смежник. Обычно это отрезвляет.

Дальше настройте один общий сетап экспорта на команду, зашейте IfcExportAs в шаблон и опишите правила в BIM-стандарте.
